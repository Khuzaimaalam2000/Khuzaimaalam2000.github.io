Research: detecting attacks run by AI agents

AI agents can now run cyberattacks on their own. My research asks whether we can catch one in the act, at the step where it issues the attack, by fusing the agent's own execution trace with host and network telemetry.

Risk, Regulation & Responsible AIAI & ML in Financial ServicesData Engineering for Agentic Workflows

I built a research harness in which an autonomous LLM agent (a LangGraph decide/act loop) attacks OWASP Juice Shop, a deliberately vulnerable web app. Each trial records three evidence streams with aligned timestamps: the agent's decisions and tool calls, host syscalls (auditd) and network packets (tcpdump). Step-level Random Forest and XGBoost classifiers then try to flag the attack as early as possible, and I compare them with a rule-based baseline I wrote in Cisco's open-source Project Quarry.

  • 510 trials (235 benign, 275 attacks across 13 categories) with an end-to-end pipeline: task generation, trial execution, labeling, feature extraction, training and evaluation
  • Rigorous design: each attack is labeled at the step where it was issued, not where it succeeded. Features use only information available at that step, and cross-validation is grouped by trial, so a trial's steps never land in both training and test data.
  • Fusion helps: combining both streams gave the best F1 (0.880). System telemetry on its own reached 0.645.
  • Lead time: both models catch 98–99% of attacks, with a median detection delay of 0 steps
  • Open problem: on attack categories held out of training, recall drops to 21–29%. Access-control attacks such as IDOR, which need context about who owns a resource, defeat every method tested. That points straight at where defenses need work next.
